# Magpie lessons 设计依据：短规则经重复观察后升入 specs

状态：active
范围：docs-notes v0.4.0 的 lessons 触发、计数与升规设计；不涉及接入流程或托管边界
核验日期：2026-10-13

证据：
- 外部只读仓库 [yetone/magpie @ 8c661279f2104484962477f82af9369b16eb8af0](https://github.com/yetone/magpie/tree/8c661279f2104484962477f82af9369b16eb8af0)（2026-10-13 核验，本地 clone 为临时目录，不随本 skill 分发）
- `LESSONS.md` 开头：每条 lesson 为 rule → why → evidence，`Seen` 记录出现该 lesson 的不同观察日期；3 个及以上独立日期移入 `docs/code-standards.md`
- `AGENTS.md` 的 Lessons 节：改动代码前先读 `LESSONS.md`
- 该版本 `LESSONS.md` 声明每晚复盘提交，但未在公开仓库中找到维护该文件的夜间调度或更新程序；只能确认文档声明与记录结构，不能据此还原或宣称我们已实现自动复盘。

问题：lessons 该怎样组织、计数与升级，才能既留住证据又不与长期规范重复？

结论：
1. **借鉴**：单条采用"短触发 → 动作 → 简短原因 → 已核验证据"结构；按错误机制合并同类项，不按表面症状堆条目。
2. **调整**：`Seen` 可选，只计独立新案例支撑的不同观察日期；重读或重复跑同一案例不加计数。3 个不同观察日期只是整理提示，不是门槛；高风险或重大影响可凭单次已核验案例直接升 spec。
3. **升规后**：lesson 只保留短指针（触发词 + spec 链接），原正文不再与 spec 双写；再犯时先检查测试与执行约束是否失效，而不是加口号。
4. **边界**：未验证推测留在 note，不写成 lesson；证据失效时更新或移出 lesson，note 历史保留。
5. **不照搬**：不引入 Magpie 的 nightly 自动复盘、固定计数状态机或复杂模板；不把其英文规范原文复制进本项目。

失效条件：用户取消升规机制，或实测发现按错误机制合并的 lesson 反而掩盖差异时重议。
