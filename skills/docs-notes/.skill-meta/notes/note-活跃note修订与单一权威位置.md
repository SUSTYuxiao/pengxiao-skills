# 活跃 note 修订与单一权威位置：规范维护条款的四条分界

状态：active
范围：DOCS_NOTES.md 托管块第 1 / 4 / 5 节——note 原位修订与 superseded 分界、单一权威位置、pending→active 正文同步、入口分层再压缩；不涉及接入与分发机制
核验日期：2026-09-16

证据：
- 用户批准的四条改进（2026-09-16 授权）：活跃 note 可维护；一个事实唯一权威位置；pending→active 正文同步；入口过长先分层再压缩
- 上游佐证：deepseek-ai/deepseek-harness SHA 0d1f50007f9bca3f52b06e1c3074fa14d5fb0720（2026-09-16 主会话核验，本轮未重验远端）——docs/AGENTS.md"每事实一个家""预算先 relocate 再 condense"；notes/implemented 随代码同步路径 / 符号 / 默认值；archived 冻结；implemented 不得保留 Proposal/Plan

问题：旧条款"notes 只增改状态"与"补充证据可原位修订"并存冲突，活跃 note 的路径 / 默认值失真无维护依据；pending 升级无正文同步要求，整篇文件可冒充已验证。

结论：四条分界写入规范 v0.3.1——
1. 事实性修正（路径 / 符号 / 默认值 / 证据 / 措辞）原位修订，保持适用范围与核验日期准确；实质推翻保留原判断，标 superseded 并写替代关系，另立新文件。
2. 一个事实一个权威位置（由"本项目布局"节指定），其余放链接；不硬编码"架构归 AGENTS"之类的固定归属。
3. pending→active 必须正文同步（结论 / 证据 / 范围 / 核验日期），未验证部分保持 pending，不整篇升级、不挪进失效条件冒充。
4. 入口先分层（操作 / 专题 / 因果各自成文互链）再压缩，不设字数门槛。

不照搬上游：implemented / archived 状态目录、双语、SHA 禁令、每任务强制 note、CI 门禁——与本规范红线"不强制统一目录状态机""不要求每次任务产 note""不新增脚本 hooks CI"冲突。

失效条件：条款在真实使用中与项目布局冲突、活跃 note 历史因过度原位修订失去防踩坑价值、或用户推翻分界时重议。
