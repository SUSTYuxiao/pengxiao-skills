# skill 接入完整结构与更新所有权：目录契约同构，更新单通道自理

状态：active
范围：docs-notes v0.4.0 对"接入其他 skill"的载体结构与更新方式；取代 `note-载体与托管边界.md` 的"只发六行约定"结论，不涉及普通项目接入
核验日期：2026-10-13

证据：
- 2026-10-13 用户明确要求（本仓升级授权）：整个项目或明确子目录作用域内固定 `docs/`、`spec/`、`notes/` 三个必备目录，并以 `AGENTS.md` 作文档入口；接入其他 skill 可作为子目录应用同结构
- 更新所有权设计选择（本次沿用旧 note `note-载体与托管边界.md` 的已核验结论）：其他 skill 接入后继续由其 Git 自有维护，不带上游托管块与分发指针；这是基于用户目录要求和旧证据的设计选择，不是用户原话
- 本仓 v0.4.0 首次产物：`references/DOCS_NOTES.md`、`references/agents-reference.md`、`references/trellis-migration.md`
- 2026-10-13 v0.4.1 扩展（同一授权）：写作参考拆为 `docs.md`、`spec.md`、`notes.md`、`lessons.md` 四份，只留在源 skill，不复制到目标；`DOCS_NOTES.md` 核心自包含；`AGENTS.md` 短模板明确宿主发现范围核验。目录契约与更新所有权结论不变。

问题：既有的"接入其他 skill 只发六行约定、不建目录"与新的"三目录同结构"要求冲突，skill 是否也要托管上游规范块？

结论：目录契约与更新所有权分开处理——
1. **目录契约同构**：接入其他 skill 时，目标 skill 目录作为 docs-notes 作用域，建 `AGENTS.md` + 自有 `DOCS_NOTES.md` + `docs/`、`spec/`、`notes/` 三个必备目录并纳入 Git；入口默认小写 `index.md`，既有入口沿用；缺内容用入口说明职责与"暂无记录"；lessons 按需用根 `LESSONS.md` 或既有短章节。目标 `SKILL.md` 维护节最多只链接 `AGENTS.md`，不重复路由。
2. **更新所有权自理（设计选择）**：沿用旧 note 依据，skill 是自我分发的 Git 产物，接入后由目标 Git 单通道维护；副本去掉 `docs-notes:spec:begin/end` 托管标记、顶部“托管说明：标记块内……”整段注释、版本标记与分发源指针。这样保留旧 note 的核心优点——不引入第二维护通道与跨设备悬空指针。
3. **区别在所有权，不在结构**：普通项目是终点消费者，可自愿托管并接收上游更新；skill 只接收一次性结构模板，后续自行演化。

不照搬的旧结论：旧 note 的"只发六行、不建三目录"作废；"拒绝托管块、拒绝双维护、skill 自包含"仍有效，已原位保留在该 note。

失效条件：出现"skill 也必须持续接收上游规范强一致更新"的真实需求时重议；届时优先考虑 pskills 分发层方案，而非恢复文档托管块。
