# notes 专项写作参考（写 / 改 notes 时按需读）

本文件是写法参考，不是目标项目运行依赖。核心职责与维护规则在 `DOCS_NOTES.md`，此处只补具体写法、好坏例子、边界与验收。不复制到目标项目。

**以下示例均为虚构写法示例，不代表任何目标项目事实；状态、证据、日期与结论接入时必须替换为真实内容，不得把示例当已核验结论。**

## 1. 写什么

`notes/` 记**因果与证据**：调查过程、根因、决策理由、踩坑。一主题一文件，文件名含主题词，落笔前先按主题查重。

**好例子（虚构示例）**

```markdown
# 预览截断计数丢失：版本戳在分页前生成
状态：active
证据：{{YYYY-MM-DD}} 复现脚本 `tests/test_example.py::test_case`（修复前失败）；
     修复后同用例通过，日志显示 {{可复现输出}}。
结论：根因是分页前生成版本戳，后续截断未计入；改为分页后统计。
失效条件：分页与统计合并为单次遍历时本结论作废。
```

根因一句话、证据可复现、失效条件明确。

**坏例子（虚构示例）**

```markdown
# 一些想法
状态：active
结论：缓存好像有问题，可能是并发导致的，先这样改。
```

无主题、无证据、把猜测写成 `active`。

## 2. 状态与修订

- `pending`：证据未闭环，禁止当事实引用。
- `active`：已核验；升级时正文同步为结论、证据、范围、核验日期，未验证部分保持 `pending`，不整篇升级。
- `superseded`：被取代；保留原判断，写明被谁替代及原因，链接新文件，两份都保留。
- 活跃 note 可原位修订路径 / 符号 / 默认值 / 证据 / 措辞；实质推翻核心结论时不默改历史，另立新文件。
- 结论成熟后迁入 `docs/` 或 `spec/` 的权威位置，note 只留证据并链接过去。

## 3. 边界与验收

- 不写任务计划、执行日志、会话记录；不存凭证、密钥。
- 不把 note 当操作授权；危险操作需单独确认。
- 验收：文件名含主题词；四项必备（状态 / 证据 / 结论 / 失效条件）齐全；证据可复现；入口列出该主题；无与 docs / spec 重复的全文结论；检索命中后核验适用性再采用。
