# Trellis 迁移参考（docs-notes）

这是一份**迁移指南，不是运行依赖**：接入 `DOCS_NOTES.md` 后，`AGENTS.md` 与 `docs / spec / notes` 可独立运转，不读取本文件、不依赖 Trellis。仅在把一个已有 Trellis 布局迁到 docs-notes 三目录作用域时按需阅读。不新增脚本、hooks 或 CI。

## 1. 迁移前清单

先记录、再动文件：

- 现有 `docs/`、Trellis spec（`.trellis/spec/` 等）、ADR、设计文档，以及各自入口（小写 `index.md` 或既有入口）。
- `git status` 中的未提交改动（含他人并行改动），逐项标出归属，迁移不得覆盖。
- 旧路径的所有引用位置：入口链接、相对引用、其他平台技能或 agent 指向的路径。
- 拟迁移文件的**内容摘要或哈希**，作为迁移后逐项核验的基线。

## 2. 迁移方式：移动优先

- **直接移动，不复制**：已有 spec 文件用 `git mv` 或等价方式**移动**到作用域 `spec/`，避免留下平行副本；不要"复制一份到新目录、旧目录还留着"。
- **不覆盖未提交改动**：有未提交改动的文件先保留其工作区版本；禁止用旧提交版本或模板内容覆盖。若目标路径已存在同名文件，先停下对比，真实冲突交用户裁决。
- **入口复用**：已有 `index.md` 或既有入口沿用原名与位置，不制造大小写迁移或两份入口；实际入口写入规范"本项目布局"节。
- **单份权威**：同一契约只留一份权威副本，其余位置改链接，不复制全文。
- **历史与 task 归档**：历史 task / workspace 按原项目约定归档，不塞进 `notes/`、不伪装成 `done` 或已完成验证；需要长期证据时迁入 `notes/` 并如实标 `pending` / `active`。
- **JSONL 旧路径**：按历史约定保留原 JSONL 路径，并在入口或 README 说明旧路径到新路径的映射；不改写历史数据。
- **移除本地 Trellis 绑定**：保留 Trellis spec 与业务历史（迁移到作用域 `spec/`，或作为只读历史保留），删除指向 Trellis 运行时的入口、hooks 注册、task 依赖与框架工具；不归档执行框架，保留与其他平台无关的独立设置。Trellis 完全退出，不提供“兼容显式再启用”的残留开关，不做软恢复、不全局改动、不擅自 `git commit` / `stash` 用户工作区。

## 3. 迁移后清单与内容核验

逐项比对，全部通过才算完成：

- 清单明确区分“保留迁移”与“退役删除”：保留文件都能在新路径找到，内容哈希与基线一致（有意的 frontmatter / 链接调整需逐条说明）；退役工具确认已从项目移除，不要求为它们创建归档副本。
- 旧路径无残引用：grep 旧路径、旧入口名、Trellis 框架与活跃技能目录，确认没有悬空链接、可执行框架工具或扫描入口残留；入口已指向新路径。
- 无平行副本：同一契约不在旧、新两处同时存在完整正文。
- 三目录入口齐备：`docs/`、`spec/`、`notes/` 各有入口（默认 `index.md`，既有入口沿用），空层写明职责与"暂无记录"。
- 无接入待填占位符与机器绝对路径残留（骨架示例 `{{...}}` 是规范内容，保留）；未提交改动仍在。
- 记录原路径、迁移 diff 与核验结果，便于回滚。

## 4. 检查其它平台入口

检查 Qoder / Codex 的技能注册、agent 定义与 hooks 是否硬编码旧路径或依赖 Trellis。`AGENTS.md` 不是 hook 或扫描开关，必须查看各平台实际注册 / 扫描目录（如 `.qoder/skills/`、`.agents/skills/`、`.claude/skills/`）确认没有残留：

- 更新指向新 `docs / spec / notes` 的入口；移除仅为 Trellis 绑定的注册。
- 保留各平台自身设置，不因迁移引入新的外部依赖。
- 发现用户全局注入时如实报告，不擅改全局配置。
- 文档、技能或 agent 注册的读取通常需要**新会话或重启**才生效；迁移说明中写明这一点，不宣称旧会话即时生效。

### 自动注入 / 强依赖 Trellis 的技能的移除标准

- **判定与位置**：会向 agent 自动注入、强制 task 流程，或依赖已退役脚本、旧 spec 路径的技能，不得留在活跃扫描路径（如项目或用户级 `skills/` 目录）。只改 `AGENTS.md` 写"不要使用 Trellis"不算关闭：`AGENTS.md` 是文档路由，不是 hook / 扫描开关。
- **先保护再移除**：移除前记录保留文件的路径映射、退役工具清单与内容哈希或 diff；历史内容与业务 task / workspace 可迁入项目历史区只读保存，框架工具不复制进仓库归档。未提交改动先做项目外本机备份并核验，再删除授权范围内的项目活技能、agents、commands、hooks、scripts 与 framework 工具；不自动提交或 stash 用户工作区。
- **作用域**：项目级移除只处理本次任务授权的作用域，不改变用户全局安装，除非用户另行明确授权对应全局路径。
- **彻底退役**：Trellis 技能与运行时不再保留、不兼容显式再启用；历史只读记录仍可查询，但不作为可执行入口。若日后重新引入 Trellis，是独立的新决策与新一轮接入，不是迁移开关。
- **核验**：grep 活跃路径确认无残留入口，记录归档位置、路径映射、内容证据与"当前不可用 / 已退役"状态。

## 5. 回滚

迁移前记录原路径、原文件与 diff（例如 `git diff` 快照或临时分支），确保每一步可回退。回滚 = 恢复原文件路径与入口引用，不动 `notes/` 中的历史证据。回滚步骤写进本次迁移记录，不写入规范正文。

## 6. 边界

- 本指南不创建目录、脚本或 hook，也不执行迁移；它只给出迁移次序与检查项。
- 迁移的写入同样受任务授权约束：只读任务不得迁移；不自动发布、提交、推送或改全局配置。
- 真实冲突（同一契约两份权威、旧结论与新事实冲突）交用户裁决，不静默覆盖。
