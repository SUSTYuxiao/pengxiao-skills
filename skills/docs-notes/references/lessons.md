# lessons 专项写作参考（写 / 改 lessons 时按需读）

本文件是写法参考，不是目标项目运行依赖。核心职责与维护规则在 `DOCS_NOTES.md`，此处只补具体写法、好坏例子、边界与验收。不复制到目标项目。

**以下示例均为虚构写法示例，不代表任何目标项目事实；触发、动作、证据与 Seen 日期接入时必须替换为真实已核验内容，不得沿用示例。**

## 1. 写什么

lessons 按需写，用作用域根 `LESSONS.md` 或既有短章节承载，不默认建 `lessons/` 目录。单条只记一个"触发 → 动作"，附已核验证据或 spec 链接。

**好例子（虚构示例）**

```markdown
### {{触发场景}}
动作：{{以后该做什么，可执行}}
Why：{{一句话原因}}
证据：{{已核验的 note / spec / 命令链接}}
Seen：{{可选：不同观察日期，如 YYYY-MM-DD}}
```

触发明确、动作可执行、why 一句话、证据可查。

**坏例子（虚构示例）**

```markdown
### 注意
动作：以后小心点。
Why：容易出错。
```

无触发、无动作、无法验收。

## 2. 触发、升规与维护

- 有已核验证据且能指导下一次行动即可写；按错误机制合并同类项，不按表面症状堆条目。
- `适用范围`、`失效` 仅在确有歧义时补；`Seen` 可选，只记独立新案例支撑的不同观察日期，重读或重复跑同一案例不加计数。
- 累计 3 个不同观察日期只是"考虑升规"的整理提示，不是门槛；高风险或重大影响可凭单次已核验案例直接升 spec。
- 升入 spec 后 lesson 只留短指针（触发词 + spec 链接），原正文不再与 spec 双写。
- 再犯时先查测试与执行约束是否失效或缺失，而不是只加口号；证据失效时更新或移出 lesson，note 历史保留。

## 3. 边界与验收

- 未验证推测留在 note，不写成 lesson；不存凭证。
- 验收：触发具体、动作可执行、Why 不复述证据全文、证据已核验可查；升规条目只剩短指针；无按症状重复堆叠的同类条目。
