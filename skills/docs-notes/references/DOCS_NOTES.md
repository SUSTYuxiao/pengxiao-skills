本文件自包含：目标作用域只需要这一份规范即可运转，不依赖任何 skill、模板或脚本。
分工思路借鉴自 DSH 文章，并非其官方规范或源码复刻；已按实际裁剪，不依赖外部原文。

## 1. 作用域与结构

一个**作用域**是整个项目根，或用户明确指定的子目录。作用域内固定三层，目录名固定为 `docs/`、`spec/`、`notes/` 并纳入 Git；入口默认小写 `index.md`，已有入口沿用原名与位置。`AGENTS.md` 是本作用域唯一文档路由入口；`DOCS_NOTES.md` 是自包含规范正文；lessons 按需，用作用域根 `LESSONS.md` 或既有短章节承载，不默认建 `lessons/` 目录。

| 层 | 记什么 | 默认入口 |
|---|---|---|
| `docs/` | 当前事实：目标、架构、操作、边界、限制 | `docs/index.md` |
| `spec/` | 当前可验证契约、不变量、失败语义 | `spec/index.md` |
| `notes/` | 证据与根因：调查、决策、踩坑 | `notes/index.md` |
| lessons | 触发 → 动作，按需 | `LESSONS.md` 或既有短章节 |

- 某一层暂无内容时，用该层入口写明职责并注明"暂无记录"，不伪造知识。
- 一个事实只有一个权威位置；其余位置只放链接，不复制全文。
- 子目录作用域只约束其内，父层 `AGENTS.md` 仍适用。子层入口只声明本作用域与文档路由，不重复父层正文。
- 跨目录任务按实际改动范围读取对应作用域规范：改哪层读哪层；涉及父层事实时同时读父层入口。

## 2. 分工：事实、契约、证据、经验

- **docs 记"现在是什么"**：目标、边界、架构、模块、操作、限制。过期就改写，永远只有一份当前真相；历史沿革去 notes。
- **spec 记"现在必须成立什么"**：可验证契约、不变量、失败语义。每条约定都要有可复现验证方式；愿望与未核验判断不写成 spec。
- **notes 记"为什么是这样"**：调查过程、证据、根因、决策理由、踩坑。活跃结论随事实原位修订，被推翻的判断保留并标替代。
- **lessons 记"下次怎么做"**：触发场景 → 动作 → 简短 why，附已核验证据或 spec 链接。有证据且能指导下一次行动就写；避免全文复述 spec。

写 note 的唯一判据：下个 agent（或三个月后的自己）不知道这些，会不会重复调查、重复踩坑或做出同样的错误修改？会 → 写；不会 → 不写。不要求每次任务产 note。

每层的最小必填要素：

- spec 每条：类型 / 范围 / 内容 / 验证 / 失败语义 / 失效条件；只写可验证的承诺。
- note 每条：状态（`pending` / `active` / `superseded`）/ 证据 / 结论 / 失效条件；证据未闭环保持 `pending`。
- lesson 每条：触发场景 / 动作 / Why / 证据；按错误机制合并同类项，不按表面症状堆条目。`适用范围`、`失效` 仅在确有歧义时补。
- `Seen` 可选，只记独立新案例支撑的不同观察日期，同案重读 / 重跑不加；累计 3 个不同日期只是升规提示，重大影响可凭单次已核验案例直接升 spec。升规后只留触发词 + spec 短链接；再犯时先查测试与执行约束是否失效或缺失，而不是只加口号。

任务计划、执行日志、会话记录不进三层文档。已明确的产品方向、版本路线属于项目事实，可进 docs，但要标清"计划 / 未验证"与生效边界，不写成当前实现。

## 3. 读写与维护规则

- **开工按任务类型只读必要内容**：动手前先读本作用域 `AGENTS.md` 的路由；代码、配置或行为变更前必读相关 `spec/`，再按实际 lessons 载体存在时匹配触发条件，按需追到 `docs/`、`notes/` 证据。架构 / 操作 / 边界 → `docs/`；证据 / 根因 → `notes/`。先读入口再按链接深入，不整目录通读。
- **接入时先判定已有证据能否指导下一次动作**：有载体沿用；无载体且确有需要才建 `LESSONS.md`，无需则收尾简述原因。
- **变更触发维护**：代码、配置或行为变更后，事实改 `docs/`，契约改 `spec/`，新证据与根因进 `notes/`，触发 → 动作型经验按需进 lessons；新增、移动或删除文档时同步所在入口；任务收尾说明维护结果或无需更新的理由，不强制新 note。
- **只读与授权边界**：只读任务禁止自动维护写入；任何写入都受本次任务授权范围约束；不自动发布、提交、推送或改全局配置。
- **结束验证**：核验链接实际存在、事实与实现一致、失效条件已更新、入口已同步；不留未替换待填项或机器绝对路径，不以"目录存在"判达标。
- **"自动维护"仅指本次任务内由 agent 执行以上规则**，不宣称后台自动、不新增脚本 / hooks / CI。

## 4. 入口写法

各层入口先回答该层"管什么、当前有什么"，再链接专题；无内容时写明职责与"暂无记录"。专题一文档、短小直白，只写本层该写的内容。

```markdown
# {{作用域}} docs 索引
目标：{{为什么存在}}
边界：管 {{...}}；不管 {{...}}
架构：{{模块 / 分层 / 数据流，或链接}}
契约：{{一句话概述并链接 spec/，不复制契约全文}}
操作：{{最小可执行用法，或链接}}
限制：{{已知坑、上限、未决问题；未核验的标"待验证"}}
深入：{{链接各专题 docs、spec 与相关 notes}}
```

入口过长先分层再压缩：操作细节、专题深读、因果证据各自成文并留链接；边界、契约、限制等关键约束不因压缩丢失。不设字数门槛。

## 5. 维护已有内容

- **更新事实**：`docs/` 内容过期直接改写，不保留旧版正文；需要在 notes 留因果。
- **更新契约**：`spec/` 内容变化时同步更新验证方式与失败语义；失效契约标明失效或迁移，保留历史链接。
- **更新证据**：活跃 note 的路径 / 符号 / 默认值 / 措辞可原位修订；实质推翻核心结论时保留旧文件并标 `superseded`，另立新文件并写替代关系。
- **更新经验**：lessons 证据失效时更新或移出，note 历史保留；升入 spec 后 lesson 只留短指针。
- **合并与升级**：接入新版本时，先定位现有托管块，按旧模板逐项比对合并：本地修改优先，真实冲突交用户裁决；版本标记只示来源，不凭版本号覆盖。
- **无变更 no-op**：内容与本地改动均无变化时不做无意义重写；不因更新而重排块外内容。

## 6. 禁止事项

- 不伪造知识：空内容只写"暂无记录"，不把猜测写成 active 或 spec。
- 任务计划、执行日志、会话记录不进三层文档与 lessons；产品路线计划按第 2 节标注后可进 docs。
- 不新增脚本、hooks 或 CI；规范是 markdown 约定，不是运行依赖。
- 不把子目录作用域规则扩到父级；不重复正文，一个事实一个权威位置。
- 不默认建 `lessons/` 目录，不强推后台自动化。
