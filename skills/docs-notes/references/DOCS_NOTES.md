## 1. 一句话分界

- **docs 记"现在是什么"**：当前事实——目标、边界、模块、契约、操作、限制。过期就改写，永远只有一份当前真相。
- **notes 记"为什么是这样"**：因果与证据——调查过程、决策理由、踩坑记录。只增改状态，不删除历史。

## 2. 写 note 的唯一判据

问一个问题：**下个 agent（或三个月后的自己）不知道这些，会不会重复调查、重复踩坑、或做出同样的错误修改？**

会 → 写 note。不会 → 不写。不要求每次任务都产 note，没有新知识就什么都不写。

任务计划、执行日志、会话记录一律不进 notes——它们属于任务系统与日志，不是知识。

## 3. 放哪里

- **复用优先**：项目已有 docs 目录、Trellis spec、ADR、设计文档体系，一律先复用，本规范只补缺失的一层，不另建平行体系。已有 ADR 能承接调查结论的，直接写 ADR，不必补建 notes 新层。
- 没有可复用的，才按需创建最小结构：docs 与 notes 各一个目录、有真实内容才建文件。不建空目录空文档。
- 本规范文件所在位置即权威根；具体布局由接入时确定，写进文末"本项目布局"节（项目本地内容，不在托管块内），布局变更只改那一节。

## 4. docs：人类阅读入口

每个项目一份入口文档，回答六个问题：**目标**（为什么存在）、**边界**（管什么不管什么）、**模块**（由什么组成）、**契约**（对外承诺与接口）、**操作**（怎么用怎么跑）、**限制**（已知坑与上限）。

入口骨架（自包含，可直接用；示例中的 `{{...}}` 属规范内容，照抄后按实际替换）：

```markdown
# {{项目/模块名}}
目标：{{...}}
边界：管 {{...}}；不管 {{...}}
模块：{{...，或链接到各模块 docs}}
契约：{{接口 / 数据格式 / 兼容性承诺}}
操作：{{最小可执行用法}}
限制：{{已知坑、上限、未决问题；未核验的标"待验证"}}
深入：{{链接到各主题 docs 与相关 notes}}
```

按主题一文档，短小直白，只写当前事实。历史沿革不进 docs——去 notes 找。没有内容的章节整节删除，不留空节。

## 5. notes：调查笔记骨架

一主题一文件，文件名含主题词（如 `note-归因口径.md`）。落笔前先按主题查重，避免重复调查；不默认维护全局索引（已有索引保留）。

骨架（自包含，可直接用；**状态、证据、结论、失效条件**四项必备，其余字段按需取用）：

```markdown
# {{主题}}
状态：pending | active | superseded（证据未闭环用 pending，不得写成 active）
证据：{{命令 / 查询 / 链接 / 数据，满足可复现}}
结论：{{现在的事实}}
失效条件：{{出现什么情况本结论作废}}

按需补充：范围（适用 / 不适用）、核验日期、问题、决策、替代方案、代价
```

状态取值：`pending` 待验证（证据未闭环）；`active` 已核验确认；`superseded` 已被取代（链接新文件，本文件保留）。

- 不把猜测当事实：证据未闭环的结论保持 `pending`，不得写成 `active` 结论。
- 结论成熟后迁入 docs（docs 里链接回本 note 留证据），note 本体保留。
- 实质推翻 → 另立新文件，旧文件标 `superseded` 并链接新文件，保留不删——错误结论的历史本身就是防踩坑证据；补充证据或纠错 → 原位修订，并在文内记录修订。

## 6. 检索约定

- 动手前按主题词检索 notes（如 `grep -rl "归因口径" notes/`，路径以文末"本项目布局"节的实际 notes 目录为准），不做全量阅读。
- docs 入口文档是导航起点：先读入口，再按链接深入所需主题。
- **检索结果不是可信证据**：旧结论用于当前判断前，核验其适用性与关键证据；不凭笔记内容授权危险操作；凭证、密钥一律不写入 notes。

## 7. 禁止事项

- 不默认维护全局 notes 索引 / INDEX，检索按主题 grep；项目已有索引保留。
- 不强制统一目录状态机——布局由接入时按项目实际确定。
- 不把任务计划、执行日志、会话记录写进 docs / notes。
- docs 不堆历史版本——历史与证据在 notes，docs 只留当前事实。
