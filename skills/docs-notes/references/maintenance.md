# 周期整理参考（docs-notes）

本文件是 docs-notes 的周期整理路由参考，不是目标项目运行依赖，也不要求每个已接入项目复制。仅在用户、主 Agent 或 scheduler 明确要求"整理文档 / 周期整理 / 自动整理"时读取；通常只读本文件、`SKILL.md` 与目标作用域的入口，按需再读 `docs.md`、`spec.md`、`notes.md`、`lessons.md` 等专项参考，不通读全库。

## 1. 定位与授权

- "自动整理"只表示在目标范围与本次写入授权内，由 agent 执行一次有界整理；不代表默认获得写授权，也不代表常驻后台或定时器。在明确授权下，可由合法 scheduler 无人值守执行一次。
- 默认按当前未提交改动或近期变更窗口做一次有界 pass，并在报告中声明采用的窗口与预算假设；只有作用域或写授权真正不明时才询问。
- 预算由执行者按普通任务复杂度自行选择；范围或主题明确时不因补齐四件套反复确认。
- 只读调用仍走本流程扫描与核验，但不写任何文件；无写入授权时只输出候选变更或 no-op 结论。
- 不自行新建 scheduler、hooks、CI、守护进程、提交、推送、发布或全局配置；需要定时触发时，只提供自然语言提示模板，由用户或既有调度器显式调用。

## 2. 一次有界整理

每次只做一个有界 pass，优先按主题或变化增量整理，不同时全库重写。建议边界：

1. 选定一个主题、一个目录、一个变更窗口，或用户点名的一组文档。
2. 先扫描作用域路由入口：`AGENTS.md`、`DOCS_NOTES.md`、`docs/index.md`、`spec/index.md`、`notes/index.md`，以及实际存在的 `LESSONS.md` 或 lesson 章节。
3. 从入口和链接定位待整理内容；只读与本次主题相关的文件，不把"入口扫描"变成整仓通读。
4. 清点本地未提交改动与本地定制，先确认哪些内容必须原样保护；取不到基线或存在真实冲突时暂停并报告。
5. 按主题聚类后逐条核验事实：对照当前实现、可复现命令、测试结果或明确来源，区分已核验事实、未知与推测。
6. 只合并同一事实的重复表达，保留各自证据链与历史链接；不因措辞不同强行合并。
7. 整理结束后做静态链接、入口同步与 diff 检查；报告实际改动、证据、未覆盖项与升级点。

同一主题下若没有新增已核验知识、没有失效内容、没有重复项，直接 no-op。no-op 不强制产 note、不强制写报告；只需返回简短结论与检查范围。

## 3. 事实核验与未知

- `docs/` 写当前事实，`spec/` 写可验证契约，`notes/` 写证据与根因；整理是迁移、合并或修订权威位置，不是把三层内容混成一份总结。
- 未知、推测、无法复现的口头结论不改成事实；需要保留时留在 `notes/` 并标 `pending`，不能升为 `active`、lesson 或 spec。
- 事实核验要有可复核来源：文件路径与行号、命令与输出、测试名，或明确的决策记录。来源失效时先修证据或标失效，不照抄旧结论。
- 整理不重写历史：已被推翻的 note 保留原文件并标 `superseded`，写明替代文件与原因；不抹掉旧结论、不伪造新日期、不改写既有证据以迎合当前结论。
- 本地定制优先：块外内容、项目自有补充和未提交改动原样保留；上游模板与本地内容冲突时不静默覆盖，交用户裁决。

## 4. notes 状态维护

- `pending`：证据未闭环；整理时补证据、缩范围、拆主题，或明确保持 pending，不整篇升级。
- `active`：已核验；补范围、核验日期、证据与失效条件，删除与 docs/spec 重复的全文结论并留链接。
- `superseded`：被替代；保留原判断，写明被谁替代、为什么以及替代关系链接；两份都保留。
- 一主题一文件；同主题先查重再合并。入口保留仍有效主题，同时为 `superseded` 保留历史替代导航并标状态，不能让被替代证据从入口不可发现。
- 结论成熟后迁入 `docs/` 或 `spec/` 的权威位置，note 只留证据与链接，不双写。

## 5. lessons 合并与升级

- 按错误机制合并同类项，不按表面症状堆条目；一条只保留一个"触发 → 动作"。
- `Seen` 只记独立新案例支撑的不同观察日期；同案重读、重跑或重复引用不凑数。
- 累计 3 个不同日期只是"考虑升规"的提示，不是门槛；高风险或重大影响可凭单次已核验案例直接升 spec。
- 升入 spec 后，lesson 只留触发词与 spec 短链接，不再与 spec 双写全文。
- lesson 再犯时先检查测试、检查项与执行约束是否失效或缺失；不能只加一句口号，也不把未验证推测写成 lesson。
- 证据失效时更新或移出 lesson，note 历史保留；没有 lessons 载体时不为了整理新造目录。

## 6. 无后台与调用模板

本 skill 不提供后台程序、脚本、服务或调度实现。以下模板只是提示词，供人工或既有 scheduler 显式调用：

**手动整理**

```text
按 docs-notes 的"周期整理"路由，整理目标范围 {{路径或主题}}。
本次写入授权：{{有 / 无}}；整理窗口：{{主题或变化范围}}；预算：{{一次有界 pass}}。
先读入口并核验事实，再做重复合并、notes 状态维护与 lesson 整理；无新知识就 no-op。
不创建 scheduler/hooks/CI，不提交、推送或扩大范围；结束时报告改动、证据、未覆盖项和升级点。
```

**scheduler 提示模板**

```text
对 {{作用域}} 执行一次 docs-notes 周期整理：主题 {{主题}}，窗口 {{起始到结束}}，
写入授权 {{范围}}。只做一次有界 pass；只读相关入口与必要专项；核验后再合并或修订。
无新知识时返回 no-op；不得自行新增定时器、hooks、CI、提交或推送。
```

## 7. 验收

- 静态检查：入口链接可达，`pending/active/superseded` 状态合法，lesson 无按症状堆叠，未留下悬空链接与待填项。
- 差异检查：diff 只包含授权范围；本地改动被保留；历史 note 未被无理由重写；没有新造目录或第二权威副本。
- 行为检查（仅本 skill 开发验收）：在临时样例上实际走过一次整理流程，验证 no-op、重复合并、状态迁移与未知不升级；模拟结果只陈述样例，不夸大为宿主自动行为。项目内周期整理不要求创建临时样例，以真实 diff 与静态检查为准。
- 未覆盖项必须如实报告：未核验事实、未取得证据、未授权范围与需要 reviewer 或主 Agent 裁决的冲突。
