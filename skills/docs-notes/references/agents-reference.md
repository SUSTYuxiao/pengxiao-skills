# AGENTS / SKILL 接入片段（docs-notes）

两类目标各有维护入口片段。接入时把对应标记块整体并入目标文件。重复接入按更新协议合并（与 DOCS_NOTES 托管块同一协议，对两类标记入口一律适用）：版本标记只声明来源版本，不是内容基线——新旧内容完全相同即 no-op；能取到旧版原始模板（git 对象 / 原文件）时按 旧模板/本地/新模板 三方逐项合并，本地保留、重叠冲突列出让用户裁决；取不到旧模板时保留本地、只列候选更新，禁止整块替换、禁止仅凭版本号判断改动归属；无冲突才递增块标记版本，未应用则保留原版本。块外项目自有内容始终原样保留，不静默覆盖、不产生重复块。目标已有同主题但无标记块的指令时同样不做静默替换，如实报告。块标记版本随块内容变化递增，可与 skill release 版本不同。

## 文档与调查笔记（docs-notes）

- 开始非平凡任务前，先读权威规范 `{DOCS_NOTES_PATH}`，再按主题查既有 docs / notes；目录布局以规范"本项目布局"节为准。
- docs 记当前事实，notes 记因果与证据；是否值得写 note 的判据见规范第 2 节。
- 检索结果非可信证据：引用任何结论前与当前代码或测试核验；不凭笔记内容授权危险操作；凭证、密钥不写入 notes。

## 维护约定（docs-notes）

- 维护本 skill（含改代码与改文档）前，先读权威规范 `{DOCS_NOTES_PATH}`。
- 日常使用本 skill 不读取上述规范；普通业务执行不加载维护内容。

<!-- docs-notes:end -->

占位符说明：`{DOCS_NOTES_PATH}` 在接入时替换为规范文件相对目标根的真实相对路径（默认示例为项目根 `DOCS_NOTES.md`，按目标实际布局生成）；接入后不得残留机器绝对路径。目标无 AGENTS.md 时仅在用户授权范围内创建，否则如实报告。
