# docs-notes：项目文档与调查笔记

一份规范、两种载体：本 skill 是**接入器与维护入口**；真正约束日常写作的是从 `references/DOCS_NOTES.md` 复制到目标根目录的 `DOCS_NOTES.md`（自包含，目标项目不依赖本 skill 的其他文件）。

借鉴声明：借鉴 DSH 文章思想，并非 DSH 官方规范或源码复刻，已按团队实际裁剪，不依赖外部原文或 PDF 路径。

## 两条操作线

| 线 | 触发 | 改哪里 |
|---|---|---|
| 接入 | 用户要求把规范装进目标项目 / 其他 skill | 目标项目的权威根 + 其 AGENTS.md |
| 维护 | 用户要求改规范本身 | 仅本 skill 源码（源仓库） |

普通业务执行**不加载本 skill**：目标项目的日常 docs / notes 写作由其 AGENTS.md 指向的 DOCS_NOTES.md 承载。接入目标是**其他 skill** 时，必须在该目标 SKILL.md 加"仅维护时读取 DOCS_NOTES.md"的标记块作为维护入口——不假设 skill 子目录 AGENTS.md 会被自动加载；目标已有 AGENTS.md 则同步加引用，未经授权不新建 AGENTS.md。普通业务不加载该 skill 的维护笔记。

## 接入流程

1. **定目标**：与用户确认目标（普通项目，或本仓某个 skill）和权威根目录——规范文件放哪、docs / notes 布局放哪。用户未指定权威根就先问，不猜。
2. **查身份**：`readlink -f` 解析真实路径后再判定，不凭路径形态下结论。解析后指向权威源码（本仓源仓库，或目标项目 / skill 真身，`~/.agents/skills` 等软链落到真身即合法）→ 可接入。解析后是分发安装副本（`.pengxiao-skills/`、`~/.pengxiao-skills/` 等安装拷贝）→ **不能作接入目标写入**（安装副本不存业务记忆），但作**模板读取来源**（只读复制规范与片段到目标）合法。无法确认权威源 → 如实报告并询问，不编造"正确目标"。
3. **查复用**：目标已有 docs 目录 / Trellis spec / ADR / 设计文档体系 → 一律复用（已有 ADR 能承接结论的不补 notes 新层）；实际布局写进副本"本项目布局"节。
4. **写规范**：把 `references/DOCS_NOTES.md` 复制到权威根，只填文末"本项目布局"节与操作路径占位；骨架代码示例里的 `{{...}}` 属规范内容，保留不清除。同名文件已存在 → 不覆盖，按**更新协议**合并——版本标记只声明来源版本，不是内容基线：
   - 新旧内容完全相同 → no-op，内容 hash 一致即收工。
   - 能取到旧版原始模板（目标 / 源仓库的 git 对象 / 原文件）→ 按 旧模板 / 本地 / 新模板 三方逐项合并：本地保留；新旧改在不同处则两边都收；重叠冲突列出让用户裁决。
   - 取不到旧模板 → 保留本地副本，只列候选更新并如实报告；禁止整块替换，禁止仅凭版本号判断改动归属。
   - 无冲突才把块标记版本升到新版；未应用的候选保留原版本号。无标记基线 → 同样不整块替换，报告冲突。块外内容一律视为项目本地定制，原样保留，不产生重复块。

   此协议对 DOCS_NOTES 托管块与 AGENTS / SKILL 标记入口（`references/agents-reference.md`）一律适用。
5. **接入口**：接入普通项目 → 把 `references/agents-reference.md` 的项目片段并入目标 AGENTS.md；接入其他 skill → 把 skill 片段并入目标 SKILL.md，目标已有 AGENTS.md 再同步引用；`{DOCS_NOTES_PATH}` 换成规范相对目标根的真实相对路径。已有同主题但无标记块的指令 → 不默默替换，报告冲突。目标无 AGENTS.md → 仅在用户授权范围内创建，否则报告了事。
6. **建内容**：仅当有真实内容才创建 docs / notes 文件（用 `references/doc-template.md` / `note-template.md`，占位按目标实际布局生成）。不建空目录空文档。
7. **自检**：实际被引用的文件必须存在；尚未按需创建的 docs / notes 目录只要求路径合法，不要求已存在；布局占位（`{DOCS_NOTES_PATH}`、"本项目布局"节）必须按目标实际填充，骨架示例占位 `{{...}}` 属规范内容允许保留，操作占位与骨架占位不得混淆误报；无机器绝对路径。
8. **人类阅读入口验收**：README / docs 现有入口须能找到目标、边界、架构、操作、限制——缺导航补链接；缺实际内容就如实报告缺什么，不编造内容，不以"目录存在"判达标。

接入完成后，目标项目不依赖本 skill 源文件或任何机器绝对路径。

## 维护

仅当用户明确要求改规范本身时走本节，且只在**源仓库**操作。源仓库判定：git 仓库且同时含 `pskills/` 与 `skills/`；路径是软链先解析到真身再判定。

1. 改 `references/DOCS_NOTES.md`。自包含是铁律：目标项目只复制这一份，禁止引用 skill 内其他文件。
2. 改 `references/agents-reference.md` 时保持 `docs-notes:begin/end` 标记块结构，这是合并定位的依据；块标记版本随块内容变化递增，可与 release 版本不同。
3. 递增本文件 frontmatter `version`；托管块内容有变时同步递增对应 begin 标记版本。
4. 行为级变化同步本仓 README.md 的 skill 清单。
5. 已接入的项目不自动跟进，由各项目重跑接入流程更新副本（按第 4 步更新协议执行）。

模板 `doc-template.md` / `note-template.md` 只是接入时的落笔辅助；DOCS_NOTES.md 已内联等价骨架，目标项目缺模板也能正常运转。

## 红线

- 分发安装副本（`.pengxiao-skills/`、`~/.pengxiao-skills/` 等安装拷贝）不作为接入目标写入业务记忆；作模板读取来源（只读）不受限。软链先 `readlink -f` 解析，写入目标须指向权威源码。
- 不默认接入本仓库自身——本仓是 skill 源，不是业务目标；用户点名才做。
- 不建空目录空文档；不要求每次任务产 note。
- 不建全局 notes INDEX；不强制统一目录状态机。
- 任务计划、执行日志、会话记录不进 docs / notes。
- 只做 markdown 规范：不新增脚本、hooks、CI。
