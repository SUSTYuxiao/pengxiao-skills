# 技术报告阅读版示例：播放日志覆盖差异

同一份技术报告的三版静态阅读版，用于观察长报告在"结论前置、按需折叠、证据回查"上的不同组织方式。三版共享同一事实基线 `playlog-coverage.md`，差别只在呈现与阅读路径。本目录是静态样例，不是 `reading-edition` 的规范来源或默认模板。

| 文件 | 版本 | 组织方式 |
|---|---|---|
| `playlog-coverage-archive.html` | 档案总册 | 大标题、档案编号、结论数字带与完整索引，首屏先给出阅读地图 |
| `playlog-coverage-dossier.html` | 研究档案 | 纸面整体居中，正文、表格与框线同宽；核心判断后接连续正文 |
| `playlog-coverage-ledger.html` | 技术台账 | 核对摘要 + 常驻索引，正文限宽、表格保留原宽，服务反复查证 |

## 示例的定位：参考与最低质量底线

这三版是**参考，不是必须遵循的样式**。可以做的是观察信息层级、留白、导航、表格密度与响应式处理；不要照搬其配色、字体组合、栏数、封面结构、章节编号或折叠位置。

同时，这几版体现的是**阅读版的质量最低标准**，也就是做不到就不算合格的部分：

- 首屏能读到结论、依据与适用范围，不必先展开细节。
- 事实、数字、口径与证据范围与源 md 一致，不因排版改变含义。
- 默认状态足以理解主要内容；折叠只改变层级，展开后信息完整。
- 导航在桌面与窄屏都可到达目标位置，页面不整体横向溢出。
- 单文件自包含：样式内联，无外部资源；默认无脚本。

颜色体系、字体家族、单栏或双栏、是否有封面、目录常驻还是收进章节，都属于按源文类型、受众和长度自行决定的部分。为贴近示例观感而修改事实、删减口径或不必要地重排章节，是错误用法。

## 使用方式

直接用浏览器打开 `index.html` 浏览三个版本。页面只使用相对链接，不依赖网络、字体服务或脚本。

生成新阅读版时按需观察即可，不必每次打开：先按当前文档结构规划阅读路径，再对照 `rigor.md` 自检。本目录不被 skill 日常流程自动加载。

## 边界

- `playlog-coverage.md` 是源报告的副本，正文内的相对链接（如 `note-v2v3对账验证过程.md`、`01_表元数据.md`）指向原项目文件，未随本示例拷贝，因此在示例目录内不可解析；三份 HTML 已将这类引用改为纯文本并保留来源地址。
- 示例未覆盖跨浏览器与真机验证。这里的检查结论来自 Chromium 下的桌面与移动宽度，不代表 Safari、Firefox 或真机同样通过。
- 报告不含凭证；示例中出现的账号或路径线索只作原文留存，不构成可执行配置。
