# v2/v3 播放日志覆盖差异 · 终版报告

**两表不能视为等价替换。** 本报告比较 v2 与 v3 播放日志终表的设备覆盖和节目清单；锚定 **20260919**。总账与共有设备节目集是全量实跑，两方向的机制解释及设备画像来自 **1/1024 抽样**，不把样本解释当作总体错误归因。

设备×节目指一个设备与一个节目的组合；only_a 是 v2 有、v3 无，only_b 是 v3 有、v2 无；both 指两侧都有记录的设备。state 是播放日状态，mapping 是设备与自然人的映射。


## 1. 差异总账

| 粒度 | only_a（v2 有 v3 无） | 占 v2 | only_b（v3 有 v2 无） | 占 v3 |
|---|---:|---:|---:|---:|
| 设备 | **57,205,167** | **19.33%** | **46,855,654** | **16.41%** |
| 设备×节目 | 293,544,580 | 13.33% | 521,182,574 | 21.45% |

两侧全集：v2 295,940,929 台、v3 285,591,416 台，交集 238,735,762 台。
**对账范围**：双方均排除 OTT（source=2）。v2 另排除 source≥100 的派生行（自然人 mapping 分发到别机的行）；v3 只取 `utdid=sim_utdid` 的本机行。

范围释义依据：原报告 §5 索引的两份对账 SQL 均明确上述过滤；留存脚本锚定 0918，本次只读取过滤条件解释原文“与 OTT”的歧义。0919 数字与证据范围仍沿用终版报告，不新增运行验证。


两个容易误读的分母：**18.32% 是“完全 v2 多”形态占共有设备的比例**，不是所有含 v2 多出节目的设备占比（后者为 18.32%＋11.55%＝29.87%）；**68.03% 是 v2 多出方向 1/1024 样本中设备×节目对的归因占比**，不是 18.32% 设备形态里的占比。27.13% 同样只属于设备×节目对口径。

**证据范围**：锚定日 **20260919**（两侧 end_time 当前同语义，取值语义与复核边界见 §2.2/§4）。总账与共有设备节目集差异为 0919 全量实跑；两侧去向机制与设备级画像为 0919 的 1/1024 抽样取证。对账 SQL 无手工过滤，复现索引见 §5；过程、历史口径与对照数字见 [note-v2v3对账验证过程.md](note-v2v3对账验证过程.md)。

### 2.2 v2 多的方向：v3 为什么没有

**0919 四桶**（1/1024 抽样，both 设备 181,958 对）：

| 去向 | 占比 | 查证结论 |
|---|---:|---|
| v3 源层无行 | 68.03% | **所查历史源表中基本无匹配记录**：早于 2026-08-13 子段 98.24%、2026-08-13 起子段 98.91% 无匹配记录（见下） |
| 同式 5s 复算在 v3 输入上未过 | 27.13% | 已排除上一行"v3 源层无行"：读取的 v3 state 输入有该设备×节目，但按 v3 正本公式复算后，正片累计 ts 票与末次 end 票均不过 5 秒；复算分类，非生产拒因（见下"闸门机制"） |
| 超 180 天窗 | 3.74% | 按 v3 现行 180 天窗口条件过滤 |
| 过闸但无输出 | 1.09% | 其中 82.8% 落在设备 500 条截断（按"设备 v3 输出顶格 500"代理判定，属观测分类；v2 侧同类截断的镜像） |

四桶对数依次为 123,793 / 49,362 / 6,814 / 1,989，合计 181,958（=both 对）；"过闸但无输出"中按"设备 v3 输出顶格 500"代理判截断的 1,647 对，属观测分类、非明确截断。

四桶互斥；第二桶的前提是 v3 state 输入已有该设备×节目行，因此不再属于"源层无行"。

**源侧查证读法**：该方向样本中的“源层无行”主体，在所查历史源表也没有匹配节目记录；设备本身大多仍在源里。未匹配不等于事件从未发生，少数历史命中却当前 state 无行的对，成因未知。

**可能的解释仅是方向**：v2 接服务端与客户端双源，v3 非 OTT 支只接 swift_hub（服务端播放事件的加工通道）；客户端覆盖可能相关，但未逐对证明。Web 上报端标签不构成渠道归属证明，也不排除其他成因。

**闸门解释：已证的是输入差，不是最终公式不同。** 5s 表示 5 秒门槛；ts 是正片累计播放时长，end 是末次播放位置。在读取的 v3 日状态输入上复算未过的分类，不是生产拒因，也不能外推为门槛算法造成的差异占比。

0919 起两侧最终 5 秒公式按同形口径比较：v2 的末次播放取值来自用户确认，本次未取得运行 SQL 独立复核。差异可能来自输入行集、ts 票、end 票或共同作用；来源覆盖与上游累计、跨 video 取行次序仍未逐对闭环到原始事件。


<details class="fold" markdown="1">
<summary>闸门证据与分类口径 · 两种样本分母、目的性样例及编号</summary>

**闸门机制**：这里的 27.13% **不是说两侧 5s 过滤逻辑不同**。0919 起两侧判定形状可视为同口径：ts 票均为正片累计，end 票均按最近播放取（v2 侧自 0919 起据用户确认，本次未独立取得运行 SQL 复核）。该桶只是在读取的 v3 state 输入上复算后，`正片累计 ts <= 5` 且 `末次 end <= 5`，因此未过 5 秒；**系复算分类、非生产拒因**。

更准确的说法是：**同形公式吃到了不同输入，或同一播放在两侧加工后的票值不同**。差异可能落在 ts 票，也可能落在 end 票，还可能两者同时存在；不能简化成"只是 ts 值不一样"。

若按"源数据差异 / 计算方式差异"分层：**最终 5s 公式不是当前可证差异**；已证差异落在闸门输入层——两侧输入行集或票值不同。这个输入差异的来源又可能包括上游来源覆盖（v2 为 tt∪ut 双源，v3 非 OTT 支为 swift_hub 单源）与上游加工口径（累计、跨 video 取行次序、窗口等），本轮未逐对闭环到原始事件。因此 a1/a6 只能证明两侧闸门输入票值不同，不能断言原始源数据不同；a7 只能证明候选 video 输入行与次序不同，分歧来源仍未证。逐例样本为目的性选取，比例不外推；上游累计口径与跨 video 取行次序差仍待量化（见 [case/差异case.md](差异case.md) §1、[note §18.2](note-v2v3对账验证过程.md)）。

> 口径注：本方向总样本 293,774 对（全量 v2-only 对口径，含 v2 独有设备），其中"同式 5s 复算在 v3 输入上未过"子集 69,766 对（0919 p2c 落盘）；上表 27.13% 为 both 口径（对应 49,362 对），两分母不同。27.13% 系**复算分类**（按 v3 正本公式在读取输入上复算），不可外推为生产拒因占比，不外推。

### 2.3 v3 多的方向：v2 为什么没有

**0919 五桶**（1/1024 抽样，样本 503,025 对，锚定 0919 分区；先看 v2 视频明细层有没有该节目行，其余按去向）：

| 去向 | 占比 |
|---|---:|
| v2 视频明细层无该节目行 | 85.28% |
| 5 秒闸门拒（复算分类） | 6.47% |
| 对账口径排除派生行（来源标记≥100，数据在、口径剔） | 6.28% |
| 自动播放行（复算分类；v3 源天然过滤自动播放为已知前提，见 §4） | 1.40% |
| 按复算归入截断与自然人 mapping 未命中（观测分类，非生产判定） | 0.57%（=v2 limit 层截断 818 对 + v2 终表 mapping/rk500 未命中 2,068 对，与维表无关） |

五桶对数依次为 428,979 / 32,531 / 31,577 / 7,052 / 2,886，合计 503,025。

**样本观察**：在无视频明细行的 428,979 对子集中，播放早于 v2 建表日的分布占 90.27%，主体指向建表日边界，与“v3 数据更全”方向一致。

- v2 视频明细表 2026-08-06 建表，v3 的 180 天窗能取到建表日前的历史，故同一批对在 v2 无行、在 v3 有行；
- **建表日前的播放分布（早于 0806 占 90.27%）是观测到的现象，不据此认定"v2 无建表前回填"**——回填与否属未证事实；
- 行级门槛（ts>0 或 end_time>0）不构成拒收解释（v2 video 层上游已生效，note §10.2）。

**其他成因的证据边界**：

- 源缺失：目标节目在 0919 当天有播放的仅 23 对（播放日三分"当天"档）——该数仅是播放时间分布，不能据此排除源缺失；
- 窗口：两侧确有 180 天机制，但仅此不足以排除边界过滤差；
