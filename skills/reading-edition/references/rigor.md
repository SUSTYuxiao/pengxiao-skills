# 严谨性自检：交付前自迭代

适用场景：HTML 阅读版初稿完成（首次转换或修订同步）后、交付前。执行模型是单次一步到位：在本次会话内完成全部自检与修正，不预设多轮用户反馈。

## 自检清单

1. 结论前置核对：文首按 generation.md「结论先行，按信息组织」交代结论/依据/范围——事故/变更过程类可用其参考例（根因一句话 + 事件经过 + 关键点，因果链与时间线按适用前置）；其他问题类型按对应结构；源 md 无清晰结论层时，需在 HTML 中补建并在此确认。
2. 零丢失核对：对照源 md 逐节核对——章节数、小节数、证据编号（E1~En 等）一一对应；全部关键数字、时间戳、消息原文、rowkey、SQL、表格行用 `grep -cF` 逐项确认命中，次数与 md 一致（内容确有减少时需能解释每一处减少）。
3. 措辞扫描：按 wording.md 三类问题（自造压缩词、文学化判断词、无佐证细节）过一遍全文；有替换时逐项核对每处替换是否改善读者理解、语义零变化、关键信息逐字保留，不以被替换词词频清零作为通过判据（grep 只用于定位受影响行）。
4. 折叠与高度复查：按 folding.md 两级清单复查常显/收起归类没有错位；折叠态正文高度仍 ≤5 屏左右。
5. 标签配对：`<details>`/`<summary>` 开闭数量一致。
6. 自包含复查：唯一 `<style>` 块、零 `<script>`、零外部 `href`/`src`。
7. 语义验收：以未参与写作的读者视角通读一遍，不回看源 md 与推理过程——能独立说出结论是什么、依据是什么、适用范围是什么；摘要引用的前置结论（如「某期结论继续有效」）须在此交代其内容或指向文内明确位置。任何一处做不到，回改结构或措辞后重验本项。
8. 浏览器实测：本地打开渲染正常、折叠交互可用、特殊字符（消息原文中的 `&`、`+I[1, ...]` 等）无转义损伤。

发现问题即改，改完重跑受影响的检查项，全部通过后交付。

## 边界情况：会话中途源 md 被修订

长会话中源 md 可能在本轮转换完成后被继续修订（补证据、措辞修订、结构重排）。此时对 HTML 做重同步：

- 先通读修订后的 md 全文，diff 出变化类型：内容增补 / 措辞替换 / 结构重排（章节增删、重编号、交叉引用变化）。
- 方向唯一：md 改 → HTML 跟随；不存在「HTML 改 → md 跟随」的路径。HTML 需要改的，先改 md 再同步；禁止 HTML 单方面新增、删改、改写内容。
- 结构重排时，HTML 章节骨架、标题编号、交叉引用一并更新（如 4.1~4.5→3.1~3.5、八章→六章逐处改）；被删内容同步删除，不得「留着备用」。
- 同步时可顺手修复 HTML 自身工程缺陷（URL 双重转义、标签未配对、失效 class），属工程修正而非内容偏离，需在改动说明中单独列出。
- 同步完成后重跑上方自检清单。
