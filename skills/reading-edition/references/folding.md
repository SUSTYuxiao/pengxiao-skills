# 折叠细则：按需披露

适用场景：HTML 阅读版篇幅超过可读预算（正文明显偏长、用户反馈「篇幅过大」）时的结构调整；受众变化后的层级调整。

## 两级清单

常显（结论层，不折叠）：
- 30 秒读懂（根因一句话、事件经过、关键点）
- 时间线概要（含证据等级标注）
- 因果链步骤
- 核心证据原文（如关键下发消息逐字内容）
- 根因分析正文、修复建议结论段

默认收起（细节层，折叠）：
- 可复现 SQL 块及其预期结果注释
- 结果表格（离线表行、维表映射行）
- 代码证据、路径清单
- 统计健康度、方法论附注

例外（收起清单中的展开项）：承载整体结构认知且展开高度可控的图（如管道图）默认加 `open`——读者需要它建立全局认知，且它不贡献篇幅压力。

## 实现

- 原生 `<details class="fold">` + `<summary>`，零 JS。
- summary 文案 = 内容名 + 规模预告（例：「E2 原始消息取证 · 4 条可复现 SQL」），让读者在折叠态就能决定是否展开。
- 默认收起不加属性；例外项加 `open`。
- 案例实测：16 处 details（1 open / 15 收起），折叠态正文高度约为全展开的一半以下。

## 高度预算

- 折叠态正文 ≤5 屏左右：不展开任何折叠块，读者应能读完全部结论（根因、经过、关键点、修复方向）。
- 超预算时的处理顺序：先移更多细节进折叠（保真层信息不动，只动层级）；仍超预算时才考虑信息删减，删减必须用户明示，不得自行决定。

## 折叠不是删减

收起 = 信息仍在文档内、展开零丢失。这与「信息删减」（用户明示触发的删除，删前需逐块验证剩余内容无孤儿信息——某信息点仅由被删部分承载时，先补进保留部分）是两个动作，不可混用。
