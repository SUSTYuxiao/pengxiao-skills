# 折叠细则：按需披露

适用场景：决定 HTML 阅读版哪些内容常显、哪些折叠，以及空间紧张时如何调整层级。

## 判据

保持默认折叠状态时，读者应能理解主要结论、方案或选择、关键依据和限制。按内容在论证中的作用分层，不按表格、代码等形式分层；承担主要说明或论证的章节不能只剩折叠入口。辅助附录可整体收起，但默认状态需说明其内容与范围。

细节层（如原始日志、SQL、代码、完整清单）是否折叠仍取决于其作用；必要图表常显，辅助材料不必为“保真”全部展开。高度预算只作参考，信息完整性优先；默认态与展开态各有职责，不靠复制整份原文兜底。

## 实现

- 原生 `<details class="fold">` + `<summary>`；折叠交互零 JS，不因图表脚本例外而改变。
- summary 文案 = 内容名 + 规模预告（例：「E2 原始消息取证 · 4 条可复现 SQL」），让读者在折叠态就能决定是否展开。
- 默认收起不加属性；默认展开加 `open`。

## 折叠不是删减

收起 = 信息仍在文档内、展开零丢失。这与「信息删减」（用户明示触发的删除，删前需逐块验证剩余内容无孤儿信息——某信息点仅由被删部分承载时，先补进保留部分）是两个动作，不可混用。
