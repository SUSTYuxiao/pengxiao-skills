# 生成细则：双层结构与单文件自包含

适用场景：把源 md 转换为 HTML 阅读版（生成阶段：受众判断与结构规划）。

## 结论层配方

- 结论先行，按信息组织：文首用最短路径交代读者最需要的三类信息——结论是什么、依据是什么、适用范围是什么。条目形态（标题、编号、bullets）按信息的自然形态选，不套固定模板。
- 事故/变更过程类参考例（按适用性取用，不为凑结构断言未证根因）：
  1. 根因一句话：一句话说清机制（主语 + 机制 + 后果），不用术语堆砌，也不用比喻；根因未证时不写死，按证据等级表述。
  2. 事件经过：编号列表，≤5 行，每行一个时间点（时间 + 动作 + 值变化），推断项标注「（推断）」。
  3. 关键点：bullets，≤6 条，按重要性降序，含证据等级与后续方向。
  - 因果链步骤：≤4 步（①→②→③→④），置于根因分析章开头。
  - 时间线：证据等级定义（实测/直接观测/推断）+ 逐行带证据来源的表格，放概要开头。
- 其他问题类型（验证、对比、方案评估等）：同样结论先行，按该问题的信息结构安排前置结论层，结构自己设定。
- 结论层内容只能取自源 md。背景缺失时不凭空补写；经授权从其他材料补入背景，先注明来源写入 md，并携带原事实的比较对象、版本、成立前提与证据等级，不借用另一组对比的结论。

## 受众自适应（最小执行）

- 默认按技术读者假设：保留全部技术细节，不做降级简化。
- 关键机制可补一句直白解释，但避免类比与比喻。
- 用户明确读者为技术背景时删除比喻层：删前逐块验证技术层信息等价、无孤儿信息（参照 case-20260826.md 的 V5）。

## 零丢失约束

- 保留源 md 的独有事实及关系；数字、时间戳、消息原文、SQL、表格行与路径准确可追溯。允许重组、去重复与语义保真的呈现性改写，不要求原文顺序或逐句常显；每项事实设主位置，摘要与原表不整段复制。
- 受众判断影响呈现层级而非独有信息总量：复现约束与独有脚注仍须保留，辅助证据可折叠。源内范围含糊时，用有据说明就地澄清，不擅改业务数值与结论。

## 单文件技术约束

- 内联：唯一 `<style>` 块 + 内联 SVG；默认零 `<script>`、禁止任何外部 `href`/`src`。
- Tailwind 只允许编译后的 CSS 内联；轻量图表脚本与占比条选择见 [visualization.md](visualization.md)，不得引入外部图表库或 CDN。
- 语义色克制：状态语义只用绿/红两色，其余用中性色。
- 字体只用系统字体栈，不引外部字体（自包含优先于字体个性）。

## 管道图与可视化要点

- 管道/链路图：优先用 `<pre>` 文本管道图（转换自 md 代码块，零成本保真）；确需 SVG 时手写内联 SVG，不引库。
- 分布 / 归因桶 / 豁免阶梯的默认表达与 Tailwind、轻量图表边界见 [visualization.md](visualization.md)。
- 折叠用原生 `<details class="fold">/<summary>`，不写 JS 展开逻辑。
- summary 标题写清「里面是什么 + 规模预告」（如「E2 原始消息取证 · 4 条可复现 SQL」）。
