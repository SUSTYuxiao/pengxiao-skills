# 结论层按问题类型组织

状态：active
范围：本结论适用于本 skill 转换的一切报告的前置结论层组织方式；事故/变更过程类报告仍可取用三件套参考例，不受本结论限制。
核验日期：2026-09-15
证据：本 skill 0.2.x 版本把「30 秒三件套（根因一句话 + 事件经过 + 关键点）+ 根因/时间线」写为所有报告的固定结论层模板；2026-09-15 评审发现：方案比较、状态评估类报告在该模板下没有根因可写，被迫硬造根因凑结构。
问题：结论层是否应对所有报告固定套用「30 秒三件套 + 根因/时间线」模板？
结论：三件套是事故案例演化出的配方，不是普适模板，被当成固定模板会让无根因的报告硬造根因。通用要求是结论先行、按信息的自然形态组织，结构按问题类型自定；根因未证时不写死，按证据等级表述。结论层内容只取自源 md：技术读者需要的当前任务背景若在源 md 中缺失，不凭空补写。
决策：三件套降级为事故/变更过程类报告的参考例（按适用性取用）；通用要求改为「结论先行、按信息组织」。
替代方案：维持固定三件套——对不同问题类型做统一详略裁断没有事实依据（只验证过事故案例），放弃。
代价：非事故类报告的结构自由度提高，交付前一致性检查无法套用单一清单，需按报告类型判断结构是否合理。
失效条件：用户重新裁定所有报告恢复固定骨架。
