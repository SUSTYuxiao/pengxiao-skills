# 可视化技术分层

状态：active
范围：本结论适用于 reading-edition 生成的一切 HTML 阅读版的图形表达与前端技术选择；不改变 md 唯一事实基线与信息零丢失要求。
核验日期：2026-09-21
证据：2026-09-21 v2/v3 覆盖差异报告阅读版首版只用表格承载分布；改为纯 HTML/CSS 横向占比条后，用户确认“这种形态不错”，并要求考虑 Tailwind 与“非常轻量”的图表能力，同时强调后者需慎重评估和视觉验收。
问题：阅读版是否应继续固定零脚本、手写 CSS/SVG，还是允许 Tailwind 与轻量图表脚本？
结论：分布、互斥归因桶、豁免阶梯默认用纯 HTML/CSS 横向占比条，并保留文本数值与分母说明；Tailwind 只允许编译后 CSS 内联，禁止 CDN 与运行时编译；轻量图表脚本只作为 CSS/SVG 无法表达时的例外，必须内联、无库、无网络、预算可控、可读，并做 JS 开 / 关双态视觉验收。
决策：0.3.3 新增 references/visualization.md，并同步 generation、folding、rigor、publishing 的技术与验收口径。
替代方案：全面允许 Mermaid / 通用图表库——会破坏单文件自包含、离线与发布稳定性，放弃；维持绝对零脚本——会排除少量高价值轻交互图表，改为分层例外。
代价：可视化验收从“样式正常”扩展到比例编码、无 JS 回退、打印、窄屏与脚本体积核查，交付成本上升。
失效条件：用户重新要求禁止一切脚本，或明确接受外部图表库 / CDN 并放弃单文件自包含约束。
